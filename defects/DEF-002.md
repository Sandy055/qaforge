# Defect Report — DEF-002

## Title
Dashboard endpoint returns 200 OK for non-existent user instead of 404 Not Found

## Severity
Critical

## Priority
P1

## Status
Closed

## Reported By
Santhosh Malarvannan — QA Engineer

## Date Reported
2025-08-02

## Environment
- Application: ToDoApp Task Management API
- Component: Dashboard — GET /dashboard endpoint
- Python: 3.9.6
- Flask: 3.1.3
- OS: macOS

## Summary
The GET /dashboard endpoint was returning 200 OK with zero counts for
usernames that do not exist in the system. This caused the application
to silently treat non-existent users as valid users with no tasks, instead
of returning a 404 Not Found error.

## Steps to Reproduce
1. Start the ToDoApp API server
2. Do NOT register any user
3. Send GET /dashboard?username=ghost
4. Observe the response

## Expected Result
404 Not Found with error message "User not found"

## Actual Result
200 OK with all counts set to zero — no indication the user does not exist

## Root Cause
The dashboard endpoint was filtering tasks by username without first
verifying that the username exists in the users store. A non-existent
username simply returned an empty task list with zero counts.

## Impact
Critical — any part of the application relying on the dashboard to
confirm a user exists would receive incorrect confirmation. This could
also expose information about the system state to unauthorized requests.

## Suggested Fix
Add a user existence check at the start of the dashboard endpoint.
If the username is not found in the users store, return 404 immediately
before computing any task counts.

## Verification
Fix applied. Test test_dashboard_nonexistent_user_returns_404 now passes.
All 94 regression tests passing after fix.
