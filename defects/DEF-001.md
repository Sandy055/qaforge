# Defect Report — DEF-001

## Title
Filter endpoint accepts invalid status values without returning an error

## Severity
High

## Priority
P2

## Status
Closed

## Reported By
Santhosh Malarvannan — QA Engineer

## Date Reported
2025-07-15

## Environment
- Application: ToDoApp Task Management API
- Component: Task Filtering — GET /tasks/filter endpoint
- Python: 3.9.6
- Flask: 3.1.3
- OS: macOS

## Summary
The GET /tasks/filter endpoint was accepting invalid status values such as
"unknown" or "done" and returning an empty result set with 200 OK instead
of returning a 400 Bad Request error. This masked input errors and could
cause users to believe a filter returned no results when in fact the filter
value itself was invalid.

## Steps to Reproduce
1. Start the ToDoApp API server
2. Send GET /tasks/filter?status=unknown
3. Observe the response

## Expected Result
400 Bad Request with error message indicating invalid status value

## Actual Result
200 OK with empty tasks list — no indication the filter value was invalid

## Root Cause
The filter endpoint was missing input validation for the status parameter.
It filtered against an invalid value which matched nothing, returning an
empty list instead of rejecting the request.

## Impact
Users filtering by a mistyped status value would receive an empty result
and assume no tasks exist matching that status, when in fact their input
was invalid. This leads to incorrect conclusions about application state.

## Suggested Fix
Add validation for the status parameter in the filter endpoint — check
that the value is one of pending, in_progress, or completed before
executing the filter. Return 400 if invalid.

## Verification
Fix applied. Test test_filter_invalid_status_returns_400 now passes.
All 94 regression tests passing after fix.
